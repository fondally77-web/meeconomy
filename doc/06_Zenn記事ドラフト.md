# 羊を刈るか肉にするか——連結会計をローグライトにした話（ドラフト）

> Zenn投稿用ドラフト v0.1。公開前に：プレイURL・スクリーンショット・所要時間の実測値を差し込むこと。

## これはなに

『メェコノミー』という**ブラウザで15分遊べる経営ローグライト**を作りました。羊の神視点サプライチェーンで、毎月ひとつの二択を迫られます。

**毛を刈って飼い続けるか、狩ってお肉にするか。**

- ✂️ 刈れば羊は残り、2ヶ月ごとに毛でなんども稼げる。ただし毎月エサ代
- 🔪 お肉にすれば大きなお金が一度きり。その子はもういない

これは実は「**資産を保有し続けるか、現金化するか**」というキャッシュフロー経営のド真ん中の問いです。会計用語をひとつも出さずに、羊のかわいい二択として体感してもらうのがこのゲームの狙いでした。

## 遊びの構造

1ラン＝1年度（12ヶ月）≒15分。毎月が「お仕事体験」の工程で進みます。

牧場で羊をタップ（✂️/🔪）→ トラックが集荷 → 紡績・と畜をタップ → レシピで加工 → 値付けして開店 → 月末決算。年度末にランクが出て、のれんP（信用）でラボ強化 → もっと強い次の期へ。

- 7社グループ（ファーム/ミート/デリカ/ウール/アパレル/セールス/ロジ）＋傘下球団メェーズ
- 月1〜2回の「帳簿ズレ探し」ミニゲーム（売り手と買い手の帳簿から食い違う1行を60秒で探す＝債権債務照合）
- 実績40個・創業日記・商品図鑑（累計原価→売値で付加価値の階段が見える）

## 会計エンジンの設計——「仕訳が唯一の真実」

いちばんこだわったのはここです。画面に出るすべての数字は、内部の**複式簿記の仕訳**から導出されます。

- 各仕訳行が companyId（利益センタ）を持ち、7社のミニP/Lは仕訳から集計
- 内部売買は現金を動かさないTRANSFER仕訳（売手：売上/原価、買手：在庫）
- **二重原価**：在庫ロットは unitCost（振替価格ベース＝会社視点）と groupCost（グループ真実原価）を持つ
- 連結利益 ＝ 外部売上 − グループ原価 − 外部経費。**消去差額 ＝ 単純合計 − 連結**

つまり「たんじゅん合計よりれんけつが小さい」という毎月のリザルト画面は、演出ではなく**本物の連結消去**です。未実現利益の消去まで正しく機能します（受け入れテストで貸借一致・検算一致を17件担保）。

## バランス調整はボットで

「idle（毎月おまかせ）は黒字率60〜75%」「季節運用が最良」「肉全振りは夏強いが年間で劣後」——という設計目標を、**戦略ボット4種×各1000ラン**のシミュレーションで検証しながら定数を収束させました。

発見だったのは、初期案では**需要が実スループットの4倍あって、季節係数が一度も効いていなかった**こと。ゲームの核のはずの「夏は肉・冬はウール」が数字上は無意味だったわけです。ボットを走らせなければ気づけませんでした。調整はすべて設計書の調整履歴に記録してあります。

## UIは3回作り直した

1. 最初は「全社への指示を1枚のフォームで入力」→ テスターの一言「**楽しくない**」
2. マップの建物タップで指示窓 → 「**指示の出し方がわからない**」
3. **毎月を工程順のお仕事体験に**（羊をタップで刈る→運ぶのを見る→紡ぐ→加工→開店）→ 「**思ったより楽しい**」

学び：経営シミュの数字は、**自分の手でモノを動かした結果**として出てこないと快感にならない。フォームは会計ソフトであってゲームではない。

## 技術スタック

- TypeScript + Vite、**フレームワークなし・ランタイム依存ゼロ**（canvas 2D手描き、効果音とBGMはWebAudio合成、ドット絵は文字列マップ）
- テスト：Vitest 23件（会計17＋バランス6）。バランステストは固定シードのボット300ランで、定数をいじって設計目標を壊すとCIが落ちる
- E2E：Playwrightでタイトル→1年通しプレイ→決算→ラボ→2期目を自動検証
- PWA（vite-plugin-pwa）でオフライン対応・ホーム画面追加
- GitHub Pages（gh-pagesブランチ）に自動デプロイ、Netlifyにも対応
